# Meeting preparation

Prepare working agendas for mentioned meetings in the planning horizon.
Resolve each meeting by date, participants, topic, and event occurrence or manual commitment ID.
Start with the invitation and any organizer-provided agenda.
Read relevant permitted messages, issues, documents, and prior follow-ups.
Use the user's rundown and mark missing context when sources are unavailable.

State the intended result and the decisions or questions the meeting must resolve.
Label an inferred purpose or suggested topic as proposed.
Preserve the organizer's sequence and keep the user's additional preparation distinct.
Prioritize consequential decisions, blockers, commitments, and dependencies.
Include only background that affects a discussion or decision.
Name an owner, attendee, deadline, or agreement only when evidence establishes that fact.
Use the confirmed duration to size the agenda; mark suggested topic durations as estimates.
Identify pre-reads, materials, and actions required before the meeting.
End with the decisions, action owners, and dates the meeting needs to establish.
Do not present desired outcomes as decisions already made.

Keep a simple check-in in the daily entry.
Use `assets/templates/meeting-agenda.json` for a meeting with several decisions or supporting context.
Link the entry to its sheet by title and keep the calendar label short.
Retain agenda evidence, proposed items, gaps, and generated_at in `run.meeting_agendas`.
Key each agenda by event ID plus occurrence date, or by the manual commitment ID.
Keep source details in the private run record; print only gaps that affect preparation.
Do not send the agenda or edit an invitation without authorization.

Examples: a product review links an open quality issue to its current proposal; a household planning talk resolves care and meal coverage.
An unavailable project tool leaves an explicit gap; a resolved issue does not remain a blocker merely because an old message mentioned it.
