# Privacy and publication boundaries

The distributable contains only reusable instructions, empty templates, software, open-license fonts, and a fictional example. It contains no account connections or author profile.

Setup writes a user's reference and tool inventory to their chosen private directory. Daily runs write notes, history, and reports there. Neither helper needs passwords or API tokens. Account authentication belongs to the host application's connection flow or an existing authenticated CLI.

Tool access is scoped per account and workspace. A personal connection does not establish access to an employer's account. A verified desktop connection does not imply an unattended job can use it. Drafting a meeting agenda does not authorize sending it or changing the calendar.

The assistant can see and process whatever the user supplies in the conversation or permits it to retrieve. This package does not change the assistant provider's data policies. The renderer embeds fonts locally and does not fetch account data.

The release manifest is an allowlist, not a folder-wide archive. Runtime state is excluded, and the audit rejects unexpected source-tree files. The optional private denylist stays outside the repository and ZIP. A passing audit does not prove that every kind of identifying information is absent; inspect content, metadata, and examples before publishing.

Do not copy real dates, schedules, messages, names, school details, businesses, contact information, file paths, or screenshots into a public example. Use a newly invented scenario. Review image content separately because a text scan cannot read pixels.
